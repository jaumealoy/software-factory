# ADR-0003 — Local-first persistence with SQLite and Drizzle

## Status

Accepted

## Context

The factory must persist its own state (projects, changes, tasks, decisions, events)
locally, and the persistence layer must be trivially deployable with the single deployable
MVP.

## Decision

Use SQLite via `better-sqlite3` with Drizzle ORM. No separate database server is required.
Migrations are SQL files under `apps/api/drizzle/` generated by Drizzle Kit. The persistence
workspace remains inside `apps/api` until a second consumer needs it, at which point it is
lifted into a `packages/db` workspace.

## Consequences

- Concurrency is bounded to a single writer; multiple processes cannot write to the same
  SQLite file without external coordination.
- If the factory grows to multiple processes in a later MVP, the adapter can be swapped for
  a client-server database (e.g. Postgres) without changing the domain model.
